# Практична робота №6 — NestJS Request Pipeline

**Варіант 4: доставка їжі та ресторанів.** Завдання взято з [index-2.pdf](index-2.pdf). Реалізовано код усіх трьох рівнів: валідацію DTO, рекурсивну санітизацію, HTTP-логування, фільтр помилок, інтерцептор часу та перевірочні сценарії.

## Запуск

Потрібні Node.js **22+** та npm. Використано NestJS 12; вимогу PDF «Node.js 18+» уточнено відповідно до сучасного фреймворку.

```bash
npm install
npm start
```

API: `http://127.0.0.1:3000/dishes`. Порт можна змінити: `PORT=3001 npm start`.

Дані зберігаються у пам’яті та очищаються після перезапуску. База даних для цієї практичної не потрібна. Сервер слухає локальний інтерфейс `127.0.0.1`.

```bash
npm run build          # компіляція TypeScript у dist/
npm run start:prod     # запуск уже зібраного застосунку
npm run test:e2e       # збірка та автоматизовані перевірки
```

Для розробки запустіть `npm run build:watch` в одному терміналі, а `npm run start:dev` — в іншому. Компілятор оновлює `dist/`, Node.js перезапускає сервер при зміні зібраних файлів.

## Стан перевірки у середовищі виконання

Встановлення залежностей було заблоковано недоступністю DNS для `registry.npmjs.org`: `EAI_AGAIN`. Офлайн-встановлення також неможливе: локальний кеш неповний (`ENOTCACHED`, зокрема відсутня метаінформація `@types/validator`; не знайдено архів `class-transformer`).

`npm run build` завершився помилкою `tsc: command not found`, оскільки залежності не встановлено. Окремо успішно перевірено синтаксис усіх 13 TypeScript-файлів через доступний локальний TypeScript 6.0.3 і синтаксис тестового файла через `node --check`. Ця перевірка не замінює перевірку типів та запуск.

**Повна збірка та HTTP-тести не пройдені. Скриншоти успішного запуску не отримано.** Наведені нижче HTTP-відповіді є очікуваними, а не результатами фактичного запуску. Після встановлення пакетів потрібно виконати `npm run test:e2e` та зберегти скриншоти консолі й відповідей API для остаточної здачі.

## Рівень 1 — DTO та ValidationPipe

| Поле | Тип | Обмеження |
| --- | --- | --- |
| `title` | `string` | `IsString`, `IsNotEmpty`; перевірка після trim |
| `price` | `number` | `IsNumber`, `IsPositive` — більше нуля |
| `weightGrams` | `number` | `IsNumber`, `Min(10)` |
| `calories` | `number` | `IsNumber`, `Min(0)` |
| `isSpicy` | `boolean` | `IsBoolean`; приймає `true` та `false` |

У `CreateDishDto` всі поля обов’язкові. У `UpdateDishDto` кожне поле має `IsOptional` зі збереженням правил. Оскільки `IsOptional` пропускає також `null`, сервіс додатково відхиляє такі значення перед оновленням сутності.

Глобальний `ValidationPipe` у `src/main.ts` має `whitelist: true`, `forbidNonWhitelisted: true`, `transform: true`. Невідомі поля спричиняють 400. Не ввімкнено неявне перетворення чисел і boolean у JSON-тілі: `"125"` та `"false"` відхиляються. Для query DTO використано явний `@Type(() => Number)`; `GET /dishes?limit=5` повертає числовий `limit: 5`.

## Рівень 2 — TrimPipe та middleware

- `src/common/pipes/trim.pipe.ts` рекурсивно очищає рядки, вкладені об’єкти та масиви, зберігаючи числа, boolean і `null`. Створює очищений об’єкт без зміни початкового.
- `TrimPipe` зареєстровано **перед** `ValidationPipe`, тому назва `"   "` після очищення стає порожньою і відхиляється.
- `src/common/middleware/http-logger.middleware.ts` записує метод, URL, статус, тривалість та IP через Nest `Logger` після події `finish`.
- Middleware зареєстровано через `NestModule.configure` для всіх HTTP-методів і шляхів. Використано іменований wildcard `{*path}`, сумісний з Express 5, включно з кореневим URL.

Очікуваний формат логів (значення часу залежать від запуску):

```text
[HTTP] POST /dishes 201 +4.23ms [127.0.0.1]
[HTTP] POST /dishes 400 +2.12ms [127.0.0.1]
```

## Рівень 3 — фільтр, інтерцептор та перевірки

`GlobalExceptionFilter` з `@Catch(HttpException)` глобально уніфікує HTTP-помилки, зокрема валідацію, некоректні параметри та відсутні сутності. Приклад очікуваної структури:

```json
{
  "success": false,
  "statusCode": 400,
  "timestamp": "2026-10-28T12:00:00.000Z",
  "path": "/dishes",
  "method": "POST",
  "error": "Bad Request",
  "message": ["property hackerField should not exist"]
}
```

`TimingInterceptor` вимірює час через `performance.now()`, використовує RxJS `tap()`, додає `X-Response-Time: <число>ms` до успішних відповідей та записує час у лог. Для помилкових відповідей заголовок не гарантується: помилки переходять у фільтр. Інтерцептор охоплює пайпи та обробник маршруту; HTTP middleware вимірює інший інтервал — до завершення відповіді.

### Маршрути

| Метод і шлях | Призначення | Успішний статус |
| --- | --- | --- |
| `POST /dishes` | Створити страву | 201 |
| `GET /dishes?limit=5` | Список, `limit` від 1 до 100, типово 10 | 200 |
| `GET /dishes/:id` | Отримати страву | 200 |
| `PATCH /dishes/:id` | Частково оновити | 200 |
| `DELETE /dishes/:id` | Видалити | 204 |

Список має структуру `{ "items": [], "total": 0, "limit": 5 }`. Невідомий id повертає 404, нечисловий — 400.

### Перевірка API

Відкрийте [requests.http](requests.http) у VS Code з REST Client і послідовно виконайте запити. Для оновлення та видалення встановіть `@dishId` у значення `id`, отримане при створенні.

| Основний сценарій із PDF | Очікувана перевірка |
| --- | --- |
| Валідний POST із пробілами | 201, очищена назва, `X-Response-Time` |
| Додаткове `hackerField` | 400, `property hackerField should not exist` |
| Рядок замість `price` | 400, уніфікована структура помилки |
| Query `?limit=5` | 200, `limit` має числовий тип |

Додаткові сценарії: граничні значення, порожня назва, від’ємні числа, рядковий boolean, PATCH, `null`, некоректний query, 404 та видалення.

Автоматизований набір `test/pipeline.e2e.cjs` використовує вбудований `node:test`, створює ізольований застосунок на вільному локальному порту та закриває його після перевірок. Окремо перевіряє вкладені масиви й об’єкти в `TrimPipe`. Набір ще не запускався через відсутні залежності.

Щоб зберегти фактичний вивід після встановлення пакетів:

```bash
mkdir -p docs
set -o pipefail
npm run test:e2e 2>&1 | tee docs/test-results.txt
```

Для звітності збережіть у `docs/` скриншоти: консолі з `HTTP`/`TIMING`, успішного POST з очищеною назвою та заголовком, помилкового POST із JSON-помилкою, завершення тестів без помилок. Після отримання зображень вставте їх у README за допомогою Markdown `![Опис](docs/імя-файлу.png)`.

## Відповіді на контрольні питання

1. **Конвеєр.** Запит проходить middleware → guards → interceptors до обробника → pipes → controller/service → interceptors після обробника → відповідь. Неперехоплені виключення спрямовуються у відповідний exception filter; фільтри не є обов’язковим етапом успішного запиту.
2. **Whitelist.** `whitelist` дозволяє властивості, позначені валідаційними декораторами. `forbidNonWhitelisted` відхиляє зайві властивості замість їх мовчазного видалення. Це обмежує mass assignment — спроби передати службові поля на кшталт `isAdmin`.
3. **Transform.** Створює екземпляри DTO та підтримує перетворення типізованих параметрів маршруту. HTTP query/path надходять як текст. У query DTO число задається через `@Type(() => Number)`; `transform: true` сам по собі не перетворює довільні числові поля JSON-тіла.
4. **Middleware та interceptor.** Middleware працює з платформними `req`, `res`, `next` перед маршрутами; підходить для HTTP-логів та наскрізної обробки. Interceptor має `ExecutionContext` і `CallHandler`, обгортає виконання маршруту та його RxJS-потік; підходить для вимірювання часу, кешування й зміни відповіді.
5. **PipeTransform.** Визначає метод `transform(value, metadata)`, який повертає трансформоване значення або викидає помилку. `value` — вхідні дані, `metadata` містить тип аргументу (`body`, `query`, `param`, `custom`), `metatype` та ім’я параметра `data`. Наш пайп не потребує metadata.
6. **Catch.** `@Catch(HttpException)` обмежує фільтр цим класом виключень та його нащадками. `host.switchToHttp().getRequest()` і `.getResponse()` надають доступ до Express request/response.
7. **Вкладені DTO.** Для властивості ставлять `@ValidateNested()` та `@Type(() => NestedDto)`, а у вкладеному класі — валідатори полів. Для масиву додають `@IsArray()` і `@ValidateNested({ each: true })`. Глобальний `transform: true` забезпечує отримання екземплярів класів.
8. **Tap.** Виконує побічну дію при події observable, пропускаючи значення без зміни. Наш callback встановлює HTTP-заголовок та логує час до серіалізації відповіді. На відміну від `map()`, не створює нове тіло відповіді.
